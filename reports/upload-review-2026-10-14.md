## 2. 按严重性排列的确认问题

### F01 · P1：教材迁移会丢失完整历史作答，却提示“没有删除”

位置：`src/state/store.tsx:96`、`:100`、`:103`、`:135`。

触发：本地学习记录的 sourceHash 或 contentVersion 与当前教材不同，且某次 attempt 的 itemId 已不在教材中。

实现先从 attempts 过滤掉整条历史记录，migrationReview 只保存 itemId、attemptId、contentVersion、note；随后自动保存覆盖原记录。原来的闭卷草稿、撤提示复述、核对项、证据和用户批注都没有进入待查条目。这个加载路径也没有先保存原始快照。

实际复现：放入一条带“不能丢失的历史作答”的有效历史记录，模拟教材变更后重开；attempts 变为 0，待查仅有四个元数据字段，所有该测试浏览器 localStorage 中均找不到原作答文本；界面同时显示“已放进迁移待查，没有删除”。

建议：迁移前保存可恢复原始快照；未匹配记录完整隔离保存，不能只保留索引。先确保数据完整，再处理重新关联与活动任务。**这是两条分支共有的旧缺陷，我上一轮版本也存在，之前的回归漏测了此边界。**

### F02 · P1：第二窗口切主题即可覆盖第一窗口的新草稿

位置：`src/state/store.tsx:133`、`src/fusion/store.tsx:85`；`src/main.tsx` 没有会话写锁。

复现：A 窗口写“旧稿”；打开同源 B 窗口；A 再输入“A窗口新增内容”，确认已落盘；B 只点击明暗切换。存储立即从“旧稿A窗口新增内容”退回“旧稿”。

原因：两个窗口各持有整份状态快照；明暗变更也触发管理学全量写入，后写的旧快照覆盖新内容，没有互斥或版本冲突检测。不是单纯“多个窗口同时提交成绩”才出现。

建议：恢复上一分支的同源单写者保护，获得锁之后才能挂载 Provider、回放事务；第二窗口只读或提示接续。明确旧程序不遵守新锁、不同来源存储不共享的边界。

### F03 · P1：Provider 持续异常时整页白屏，无独立备份入口

位置：`src/main.tsx:13`、`src/fusion/store.tsx:55`。

入口仅处理 recoverImport 返回的错误，Provider 和后续渲染树外没有 ErrorBoundary，HTML 也没有独立于模块的恢复入口。

复现：在 FusionProvider 的额外存储读取位置持续注入读取异常；浏览器捕获“模拟Provider初始化读取失败”，最终 body 文本为空，没有备份或重开控件。一次性异常可能被 React 重试恢复，因此实际探针使用持续异常，未把单次 React 重试警告误报为白屏。

建议：恢复独立的运行时错误边界及启动兜底，二者均不能依赖已损坏的应用 Context。原始备份保留坏 JSON 和事务日志，不自动重置学习数据。

### F04 · P1：失效的当前题目 ID 会永久阻塞今日流程

位置：`src/fusion/planner.ts:95`、`:99`、`:116`，`src/coach/recallAdapter.ts:25`。

触发：教材更新移除了当前未完成训练对应的 itemId，平台 active 和 MRC recall 仍指向该 ID。

复现：刷新后依旧推荐“继续训练”；点击后仅显示“管理学草稿与当前任务冲突”；active/recall 的 removed-id 都没有处理。未完成任务又禁止收工，没有清晰的用户恢复路径。

原因：reconcileMrc 在确认 active/recall 匹配后提前返回，未确认题目仍存在；prepareCoachState 仅比较 task 与 recall 的 ID，二者一起失效时不会清除或隔离。报告说“部分缓解”，但该场景仍完全阻塞。

建议：把失效草稿完整转入可恢复区，给出明确接续/迁移动作，再处理当前任务与预算。不能以直接删除历史或静默清空草稿“修复”。

### F05 · P2：全选主体小标题会撤销已勾选的体育转写/二级要点

位置：`src/views/Recall.tsx:136`。

复现：先勾“（六）体育转写”，再点“主体小标题都写到了”；此前已选体育 checkpoint 被取消。

原因：按钮把 checkedPointIds 替换为一级非体育、非扩展列表，而不是与现有选择合并。可连带改变 sportsExampleMissing、examReady 和遗漏结果，虽然证据引擎公式本身没变。

建议：合并并去重当前选择；清空由独立“清空勾选”负责。上一轮分支已有保留额外勾选的修复和浏览器测试，本交付未合入。

### F06 · P2：非法信心值可通过整包导入，提交后导致下次启动保护锁定

位置：`src/fusion/validateMrc.ts:27` 对比 `:22`，`src/state/store.tsx:135`。

触发：待继续草稿 selfConfidence=9，其余整包字段合法。正常页面按钮不能选择 9，这是导入校验边界缺陷。

实际通过文件选择器导入这份合成整包，预览与确认成功；继续并提交后，attempt.selfConfidence=9 被写入。刷新时 attempts 校验要求 <=5，程序显示“本地记录损坏”，训练被保护性禁用。

建议：草稿与 Attempt 同样要求合法范围/整数，在实际写入边界也校验，而不是让同一份被接受的草稿生成随后被拒绝的记录。不需要更改 evidence 定义。

### F07 · P2：核对原文仍丢失表头

位置：`src/views/Recall.tsx:118`。

实际教材期望列标题：空首列、政府管理型、社会管理型、结合型。浏览器 `.compare th` 数量为 0；该页只渲染 table.rows。共享 DataTable 已有正确表头，但 Recall 未使用它。

影响：比较题失去列归属，属于教材语义缺失。建议复用正确的表格组件，或显式渲染 headers；不要把缺失表头当成纯美观问题。

## 3. 版本分叉与保留能力

以先前 GitHub `273a4ca` 作为比较基线，这份上传包没有：

- 体育概论政策热点五讲的内置资料与解析脚本；新用户通用题库只有运动生理学 60 题。
- browser 层的会话锁、独立恢复界面与启动失败备份。
- 教材逐题差异修订模块。
- 上一轮新增的 policy、recovery、audit-completion 测试及相应浏览器脚本。
- 消除三个开发依赖告警的构建替换。

这些是可复核的交付范围差异，不是因为测试数量少就判定质量差。报告本身已经承认分叉，不能把它误读成“Argon、DeepSeek、Composer 的所有修复均合并”。缺少内置政策包也不等于已经导入的政策记录一定会被删除，应区分内置安装与既有数据兼容。

另一分支也有值得保留的变化：共享主题 Provider、分段外观设置、章节分组、状态提示、Windows Chrome/Edge 探测及 Node 打包、两项有效的任务修复。不能用整体覆盖方式把另一条分支的安全与教材能力抹掉。

## 4. 对报告中三项 P1 修复的判断

| 原编号 | 复核 |
| --- | --- |
| P1-01 chapterKey `.replace` | 原式 `title.match(...)?.[0].replace(...)` 在 match 为 null 时沿连续可选链短路，返回 undefined，不会调用 replace；String.match 非空结果的第 0 项也存在。实际原式/新式均返回 undefined。添加 `?.` 无害，但不能记作修复一个已经证实的崩溃。 |
| P1-02 stale tasks 占预算 | 修复有依据，新增测试确认无 recall 的陈旧任务过滤后预留分钟由 15 变 0。主要在旧 Coach 兼容路径；不能据此推断失效题目迁移已解决。 |
| P1-03 双 in_progress | 修复有依据：恢复另一 MRC 草稿前移除陈旧的 MRC 进行中任务，保持 validatePlatform 的单任务约束；不解决 F04 的双方同时指向失效 ID。 |

## 5. 已知规则与残余风险，避免误报

- 通用评分“忘记”后同日立即再次到期确实存在。原单测明确断言一个 10 分钟任务在 60 分钟预算内可连续训练 6 次，然后收工。它不是无限循环，但对“私人教练”的任务节奏有明显影响，应单独决定是否引入教练层冷却或防连续派同题；未必要先修改冻结 FSRS 公式。
- 遗漏项截止时间被推迟的问题已有测试，旧截止保留；生理学 4 道仅查询题也确实包含在 60 题中，不重复报这些旧问题。
- 原文来源 hash、itemId、schemaVersion、内容版本和冻结引擎校验通过。本次发现主要在持久化、迁移、交互和交付整合，不能由此推断学习公式出错。
- 3 项 high 属开发依赖的传递链告警，不能写成三个可通过离线应用远程利用的漏洞；也不能将其忽略为“已经消除”。
- 未做实体华为/Safari/Edge、读屏和无限历史规模认证；34 个正常旅程通过不覆盖故障恢复、并发或所有输入。

## 6. 建议的修复/整合次序

1. 以保留政策资料、会话锁和独立恢复入口的较完整分支为整合底座，保存这份交付快照；不用上传包整体覆盖。
2. 优先修复 F01 的完整历史保留，并一并处理 F04 的失效当前任务。两条分支都需纳入测试。
3. 选择性移植有效预算/任务修复及需要保留的 UI/Windows 构建支持。
4. 恢复或修复 F02/F03/F05/F06/F07，并让上述独立复现变成持续回归。
5. 重新验证三科内置资料、旧整包恢复、未完成训练、两窗口写入冲突、版本迁移、单文件产物一致性，然后再决定发布基线。
