# 用户体验审计与改进

基线：`44591d1`；改进分支：`feat/ux-journey-audit`。按用户任务、状态一致性、错误预防、恢复能力、可访问性和移动布局检查。覆盖主要页面及内嵌管理学工具；这是一次本地离线产品的工程验收，不是商业产品认证或真实用户可用性研究。

## 发现与处理

| 优先级 | 可复现的问题 | 改进后的行为 |
| --- | --- | --- |
| P1 | 恢复导入前备份一键覆盖当前记录 | 原生模态确认，先说明替换范围和新记录风险；默认焦点在取消，支持 Esc，可先导出当前整包；两处恢复入口统一处理 |
| P1 | 考试“结束”立即清除作答，用户可能误以为已归档 | 结束前说明作答不自动生成档案，提供导出／继续／确认清除；考试计时逻辑不变 |
| P1 | 资料录入后切换查询科目，可能把原草稿保存到错误科目 | 保存目标固定在录入草稿中并明确显示；页面切换保留草稿；刷新／关闭前提醒保存 |
| P2 | 手动收工后只能间接增加预算才能恢复 | 提供“恢复今日训练”，仅解除主动停止，保留原预算、已开始任务及配额 |
| P2 | 预算不足、关闭新学、章节限制都称为“今日已完成” | 按真实原因解释，并给恢复、查看安排或资料库入口，不暗示所有题已掌握 |
| P2 | “调整今日预算”实际也修改后续默认值 | 今日临时调整与每日默认设置分离；默认设置仍同时应用到今天；不隐式解除收工 |
| P2 | 数字输入每敲一位就写入，清空可能保存0或无法编辑 | 本地编辑，Enter／离开输入框才提交；非法值不覆盖，Esc 撤回，显示反馈；小数权重兼容保留 |
| P2 | 合法导入的240等预算没有匹配选项，选择框为空 | 自动包含当前值，保留15–600分钟有效预算，不重写导入记录 |
| P2 | 单纯修改科目权重也重选当日章节 | 仅明确修改新学数量或章节配额才重新选择，不因权重输入改变章节 |
| P2 | 搜索无结果提示去导入文件，容易让人误以为资料丢失 | 区分无资料与无匹配；显示结果数量，提供清除筛选；切科目清理查询条件 |
| P2 | 点击长列表下方题目，详情在顶部不可见 | 打开详情定位并交接焦点；收起回到原题按钮 |
| P2 | 管理学子页面一律返回首页，破坏查询／记录路径 | 返回对应的全科资料库、记录或设置入口；考试归在设置工具下 |
| P2 | 切页面留在旧滚动位置，读屏标题不更新 | 路由或训练阶段变化时定位主内容、回顶并更新页面标题；输入中不抢焦点 |
| P2 | 手机设置依赖横向表格 | 科目卡片随宽度排布；保留原字段和范围 |
| P2 | 已完成通用训练仍显示“暂停” | 显示“回到今日”，并标明闭卷／核对／保存三个步骤；完成后可直接收工 |
| P3 | 记录只说遗漏几项，没有实际要点 | 可展开具体遗漏，并回到今日推荐；参考题不计入可训练到期数量 |
| P3 | 管理学旧设置导入读取异常无反馈 | 捕获文件读取错误，支持重选相同文件；不改导入引擎 |

## 覆盖的用户旅程

1. 新用户：内置管理学和60道生理题，首页只保留一个训练主按钮；4道参考题不进入自动训练。
2. 训练：MRC原提示链、通用闭卷冻结与评分、保存、下一项、预算终止；暂停刷新保持同一任务。
3. 收工：等待复测、配额受限、预算不足、主动结束各有解释；恢复当天安排不清零学习进度。
4. 查询与录入：科目、章节、搜索、空结果、题目详情、草稿跨页面、明确保存科目。
5. 学习记录：MRC档案和错漏入口、通用原始草稿、具体遗漏、回到训练建议。
6. 设置与数据：默认／临时预算、数字编辑、旧JSON预览与导入、导出下载、取消恢复、确认恢复、存储故障。
7. 管理学工具：资料库、档案、错漏、方法、阅读、详细设置、闭卷考试；禁止隐式清除本次考试。
8. 可访问性与适配：主内容焦点、返回焦点、模态焦点与Esc、输入快捷键保护、减少动画偏好、手机主要页面和管理学工具。

## 保留边界与待验证项

- 没有改变教材、itemId、sourceHash、schemaVersion、contentVersion、MRC提示链／Evidence／Schedule、通用FSRS核心或冻结HTML。预算作用范围和返回路径属于本次明确修改的产品行为。
- 新学章节锁定仍保留；修改配额才重选，收工恢复不重置当日预算。此次没有增加跳过任务、任意刷题或新记忆算法。
- 教材录入草稿是会话状态，未保存即不进入教材和备份。关闭警告受浏览器限制；训练草稿仍沿用持久化逻辑。未新增完整编辑／删除教材功能。
- 暂无跨窗口写入锁，不能保证多个窗口同时训练互不覆盖；没有完成大规模长期数据或异常断电压力测试。
- 没有实体华为、Windows Edge、移动软键盘与专业读屏软件实测；自动化无横向溢出不等于完整无障碍合规。
- 3项开发依赖告警仍在。此报告不把“已检查全部主要页面”表述为“整个项目所有风险清零”。
- 上线级可用性判断还需真实用户试用：首次开始是否顺畅、一次完整训练能否独立完成、能否正确完成备份恢复。本次没有虚构这些用户研究结果。
