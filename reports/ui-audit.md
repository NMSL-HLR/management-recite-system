# 346 记忆引擎：界面复用与项目审计

审计日期：2026-10-13。基线提交：`47b6b804d34efc5dad156ec24f4aa6aebe1cf7a0`。工作分支：`feat/346-ui-audit`。原融合分支、main、V2.2.2、Alpha Lite 和 V13 冻结 HTML 保留。

## 界面结果

按上传的旧 V13 HTML 实际画面及 v7.3 源码还原视觉语言：浅绿渐变、深色描边、半透明卡片、硬阴影、绿色主按钮。恢复灵像素、通透风、像素风三主题，保留暗色阅读；没有加载远程字体、图标或图片。

桌面侧栏显示四个主要入口，手机改用顶部品牌与底部导航。今日页面显示预算进度、一项当前训练、推荐理由与预计时间，只有一个主要开始按钮。资料库、设置、记录、管理学原有训练页面统一使用相同的视觉样式。主题使用独立 `data-skin` 和 `346-fusion-theme-v1` 偏好键，不占用 MRC 的明暗、字号及专注阅读设置；可读取旧 `ms346_theme_v1`，不改写旧键。主题偏好是本机设置，不进入学习数据整包。

## 审计范围与已修问题

检查了全科候选与预算、跨日和未完成训练、管理学 Recall/Evidence/Schedule 的适配边界、通用 FSRS 数据、考试视图与原计时引擎、两份存储的导入恢复、JSON 兼容、资料渲染、布局与构建依赖。修复集中在界面、校验和适配层。

| 问题及触发方式 | 影响 | 修复与验证 |
| --- | --- | --- |
| 旧 JSON 的 `quotaChapterOverride` 为数字、日志草稿为对象 | 选题 `.trim()` 或记录页渲染崩溃 | 预览阶段拒绝错误字段；单元测试和真实浏览器验证不写入 |
| MRC 备份中的笔记、考试答案、证据附属字段或间隔设置不合法 | 页面异常，或负数间隔进入后续调度 | 在融合导入边界校验；仍调用原导入引擎合并，不改证据或复测公式 |
| 任务的 module/status 使用字符串强制转换校验 | 数组等错误类型通过校验，进入不一致状态 | 改为严格类型与枚举检查 |
| 部分旧备份省略 settings 或只提供一项配置 | 当前保持率设置被清空 | 合并明确提供的设置，保留未提供的原设置 |
| 日志由活动列表移到归档后再次导入 | 同一 log id 在两处重复，记录重复计数 | 跨活动/归档按 id 合并；同包重复相同记录只保留一次，不同内容同 id 拒绝并提示 |
| 恢复日志第二个值损坏 | 第一个键已写入，第二个才报错 | 写入前完整检查两份恢复值；测试确认损坏日志不改动任一键 |
| 整包提交后 removeItem 清理失败 | 留存旧的 committed 快照，可能覆盖随后训练 | 返回需要恢复标记；立即重新打开，先执行恢复流程再允许训练。回滚与失败后残留日志同样处理 |
| 恢复暂停任务时平台写入失败 | 仍误进入训练页 | 检查保存结果，失败停留首页且保留草稿 |
| 回滚目标原本没有 MRC 存储 | 误沿用导入后的当前 MRC 记录 | 恢复为默认空记录；并拒绝字段缺失的回滚备份 |
| 文件读取失败或换文件失败 | 未捕获异步异常，旧导入预览仍可确认 | 捕获 File.text 异常、提示重选、清理陈旧预览 |
| 本地 MRC JSON 可解析，但笔记等字段损坏 | 启动后页面崩溃或继续写坏数据 | 启动时校验，保护原存储、禁用训练，保留原始数据导出入口 |
| 考试揭晓后作答框仍可编辑 | 原始输出会被事后修改 | 揭晓后 textarea 只读；刷新保持；下一题重新可写 |
| 考试倒计时依赖全局 30 秒刷新 | 显示跳动，揭晓后仍继续走时 | 视图每秒刷新，揭晓后显示原引擎封存用时；原考试计时函数未改 |

详细设置原先可输入负数或把空输入转成零，导致无效的复测间隔；现在普通时长拒绝负值，复测间隔要求大于零，默认值和调度公式不变。浏览器验证拒绝负数后仍能正常刷新恢复。

另外修正了管理学资料跳转的外层路由适配、通用训练时的导航选中状态、受保护数据的单模块导出入口，以及窄屏按钮组换行。

## 依赖审计及剩余限制

升级 Vitest 到 4.1.11、puppeteer-core 到 25.13.0，显式安装 `@types/node`；开发环境需 Node 22.12+。审计告警从 13 个依赖项（包含 2 个 critical）降为 3 个 high，均来自开发打包链 `vite-plugin-singlefile → micromatch → braces` 的同一未修复嵌套模式问题。braces 当前发布版本仍为 3.0.3；未采用 npm 建议的旧 singlefile 大版本降级，以免破坏 Vite 单文件构建。本项目仅用受控构建模式，不向该依赖传入用户 JSON 内容。这三个开发依赖不打包进离线 HTML。生产依赖审计为 0 告警。

详细结果：[完整依赖审计](dependency-audit.json)、[生产依赖审计](dependency-runtime-audit.json)。因此本次不宣称项目「零漏洞」或「没有任何 bug」。

尚未实测 Windows Edge、华为浏览器和实体手机。关闭重开验证为同一浏览器上下文的新页面，不等同于完整浏览器进程重启。当前本地存储未实现多窗口写入锁，不应同时在多个窗口编辑同一份学习数据；大规模多年日志下的容量上限与性能也未完成压力测试。

旧 V13 的评分撤回、已有条目编辑/删除、易混对照等仍属此前融合 Alpha 的未接入功能，未作为本次 UI 复用额外扩建。对应原数据与旧版 HTML 仍保留。
